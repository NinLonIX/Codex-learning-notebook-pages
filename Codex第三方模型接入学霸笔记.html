Codex 接入第三方模型
DeepSeek 等国产模型：协议、配置、验证与风险边界
来源：AI 编程指南 · 05 接入 DeepSeek 等第三方模型 ｜ 教程更新 2026.09.01
01 · 先记住：这是实验性玩法
Codex 是 OpenAI 自家的产品，官方并没有把 DeepSeek 等第三方接入作为默认主线。能不能跑通，取决于第三方平台是否支持 Codex 当前要求的接口协议。
最大变量不是配置语法，而是协议兼容
Codex 通过 model_providers 指向自定义提供商，主要认 OpenAI 风格的 Chat Completions 或 Responses API；官方配置路线现在以 Responses API 为核心，很多第三方平台只实现了 Chat Completions。
不要把 Claude Code 的第三方接入经验直接套过来：Claude Code 更偏环境变量与 Anthropic 协议，Codex 更偏 config.toml 与 OpenAI 协议。
02 · 到底值不值得接？先看取舍
第三方优点价格通常更低，部分国产平台可国内直连，适合日常增删改查和技术练手。
第三方代价协议可能不兼容，模型名和地址会变化，官方能力和稳定性没有兜底。
官方 GPT登录即用、长链路和复杂任务更稳，跟随 OpenAI 官方更新。
✓可以试：API 账单压力大、任务偏日常、需要国内直连、愿意折腾。
✓先别试：已经买了 OpenAI 订阅、主力做复杂架构 / 疑难调试、只想省心。
先确认自己不是“重复付费”：订阅里已经有 Codex 额度，再额外接 API 可能并不划算。
03 · 两条路线：直连配置 vs 协议代理
Codex→ OpenAI 协议→ 第三方模型
路线一手改 ~/.codex/config.toml，透明、官方留口子，但完全看第三方是否支持 responses。
路线二使用 CC Switch 等社区代理工具，在本机做协议转换，图形界面更友好，成功率通常更高。
选择建议想理解原理选路线一；只想快速跑通选路线二，但要接受多一层黑盒和社区依赖。
04 · 手改配置：四个字段要认清
用户级配置文件：macOS / Linux 在 ~/.codex/config.toml，Windows 在用户目录下的 .codex\config.toml。
name提供商显示名。
base_url第三方 API 地址。
env_key从哪个环境变量读取 API Key。
wire_api接口协议；官方配置路线要求 responses。
顶层两项model_provider 选提供商，model 选模型。
不要覆盖保留的提供商 id：openai、ollama、lmstudio。自定义 id 另起名字。
05 · 最小配置骨架：Key 不进文件
# macOS / Linux
export DEEPSEEK_API_KEY=<你的 DeepSeek API Key>

# Windows PowerShell
$env:DEEPSEEK_API_KEY="<你的 DeepSeek API Key>"
# ~/.codex/config.toml
model_provider = "deepseek"
model = "<以官方文档为准>"

[model_providers.deepseek]
name = "DeepSeek"
base_url = "<以官方文档为准>"
env_key = "DEEPSEEK_API_KEY"
# wire_api 默认 responses
✓API Key 放环境变量，配置文件只引用变量名。
✓模型名与 base_url 不写死，始终查第三方官方文档。
✓Key 当作钱包钥匙：不提交 Git、不发群、不写进公开配置。
06 · 验证：先看模型，再发最小请求
codex
/model

# 也可以启动时指定
codex -m <模型名>
进入会话后先确认当前模型已经切到自定义提供商，再发送无害的最小测试：“你好，请用一句话回复确认你能正常工作。”
正常回复配置和请求链路基本接通。
401Key 错、环境变量未生效或 env_key 名字不匹配。
400高概率是 Responses API 协议不兼容；换代理路线或换支持的模型。
模型不存在模型名写错或平台改名，回官方文档查最新值。
撞到 400 不要先怀疑 TOML。配置语法正确，也可能因为第三方没有实现 Codex 需要的协议而失败。
07 · 接通后：调思考深度，别一把梭
model_reasoning_effort = "medium"
可选档位通常包括 minimal、low、medium、high、xhigh（具体支持取决于模型）。
日常任务medium：速度、质量和成本较平衡。
硬任务临时升到 high，让它多做跨文件推理。
别全程拉满第三方接入本来为了省钱，推理强度全开可能把省下的钱又烧回去。
接入第三方后，一些深度绑定 OpenAI 的能力可能缩水或不可用；把它当实验性本地编程通道，不要默认等价于官方体验。
08 · 接入篇小结
省钱之前，先确认协议能通
  • 根本差异：Codex 走 config.toml 和 OpenAI 协议，别照搬 Claude Code 经验。
  • 路线选择：手改配置透明但看协议运气；代理工具上手快但多一层黑盒。
  • 配置要点：环境变量存 Key，model_providers 定义提供商，顶层指定模型。
  • 验证顺序：/model 看切换，再用最小请求实测。
  • 排错口诀：401 查 Key，400 查协议，模型不存在查官方名称。
先问“能不能通”，再问“省不省钱”
如果你已经有稳定的 OpenAI 订阅，官方模型通常是更省心的主力；第三方接入更适合作为实验、国内直连或日常轻任务的补充。
